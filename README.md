## HTML의 탄생 - 팀 버너스리와 월드와이드웹

### 1) CERN에서의 제안
- 팀 버너스리(CERN의 소프트웨어 엔지니어)는 "정보 관리: 제안(Information Management: A Personal)"이라는 문서를 통해 하이퍼텍스트 기반의 CERN 내부 문서를 연결하는 시스템을 제안했다.

그는 문제를 해결하기 위해 세 가지를 설계했다.

| 요소 | 역할 |
|---|---|
| HTML (HyperText Markup Language) | 문서의 내용과 구조를 표현하는 언어 |
| HTTP (HyperText Transfer Protocol) | 문서를 네트워크로 주고받는 통신 규약 |
| URL/URI | 문서(자원)의 위치를 가리키는 주소 체계 |

즉, HTML은 갑자기 등장한 것이 아니라, "문서를 어떻게 표현하고, 어떻게 주고받고, 어떻게 찾을지"라는 하나의 큰 그림 안에서 탄생했다.

### 왜 하필 마크업 언어인가?
- 팀 버너스리는 이미 널리 쓰이던 SGML이라는 문서 마크업 표준을 참고했다.
- SGML은 문서에 <태그>를 붙여서 제목, 목록 등 구조적 의미를 표시하는 방식이었다.

**이 방식을 선택한 이유**
1. 이미 선택한 방식이라 배우기 쉬웠다.
2. 텍스트 기반이라 어떤 컴퓨터에서도 읽고 쓸 수 있었다.
3. 태그가 의미를 나타내므로, 프로그램이 다르더라도 해석할 수 있었다.

위 3가지의 이유에 문서와 문서를 연결하는 하이퍼링크 기능을 얹은것이 HTML의 발명이었다.

### 3) 최초의 웹
- 팀 버너스리는 1990년에 최초의 웹 브라우저 겸 편집기인 월드와이드웹(WorldWideWeb)과 최초의 웹 서버를 만들었다.
- 1991년에 이 기술을 CERN 밖으로 공개했고, 오늘날 월드와이드웹의 시작이다.
- 당시 HTML은 태그가 20개 남짓밖에 없었다.(제목, 문단, 리스트, 링크 등)

## 표준화와 발전 과정 - 브라우저 전쟁
### 초기 확산과 혼돈
- 19993년에 모나리자(그래픽 브라우저)가 생기면서, 일반 대중도 웹을 사용하기 시작했다.
- 이후 넷스케이프(Netscape), 인터넷 익스플로러(IE) 등 다양한 브라우저 회사들이 경쟁하면서, 각 회사가 해당 브라우에서만 되는 태그들을 마음대로 추가했다. 이것이 브라우저 전쟁이다.
- 이는 특정 브라우저에서는 정상적으로 잘 보이지만, 다른 브라우저를 사용하면 깨지는 문제가 심각해졌다.

### 표준화 기구의 등장
이 혼란을 정리하기 위해 팀 버너스리는 1994년 W3C(Wodrld Wide Web Consortium)을 설립했다. W3C는 모든 브라우저가 똑같이 해석할 수 있는 공통 규격을 만드는 역할을 하였다.

### XHTML의 실패, 그리고 WHATWG의 등장
- 2000년대 초, W3C는 HTML을 더 엄격한 XML 기반으로 만드려 했다. 문법을 엄격하게 검사하고, 조금이라도 틀리면 화면이 아예 안 뜨는 방식이었다.
- 하지만 브라우저 회사들은 엄격함이 아니라, 비디오 재생과 같은 새로운 기능을 추가하는 것을 원한다며 반대했다.
- 2004년, 브라우저 회사들이 독자적으로 WHATWG(Web Hypertext Application Technology Working Group)를 만들어 별도로 HTML을 발전시키기 시작했다.
- 결국 2009년에 W3C는 XTML을 공식적으로 페기하고, WHATWG의 작업을 이어받아 HTML5로 통합하였다.

## HTML5의 등장 배경 - 웹이 곧 앱
2000년대 중후반부터 웹의 역할이 크게 바뀌었다. 예전에는 신문을 읽듯이 문서를 보는 곳이 웹이었다면, 이제는 이메일, 지도, 동영상, 게임까지 돌아가는 애플리케이션 플랫폼으로 역할이 확장되었다.

기존 HTML4로는 이런 요구들을 감당하기 어려웠다.(동영상을 재생하려면 Flash와 같은 별도 플러그인이 필요했다.) 그래서 HTML5는 아래와 같은 목표를 가지고 설계되었다.
- 플러그인없이 브라우저 자체로 멀티미디어를 재생한다. -> <video>, <audio>
- 자바스크립트로 그림을 그리거나 게임 화면을 그릴 수 있는 공간이 있어야 한다. -> <canvas>
- <div>만 남발하던 방식을 벗어나 해당 부분은 무슨 의미인지 명확히 해야 한다. -> 오늘날의 시맨틱 태그(header, footer, maoin, article, ...)
- 로컬스토리지, 오프라인 지원, 위치 정보 API 등 기존 웹을 벗어나 앱스러운 기능이 있어야 한다.

즉, HTML5는 단순 웹 페이지에서 웹 애플리케이션으로 넘어가는 시대적 요구사항에 대한 응답이었다.

## 왜 아직 HTML5일까?
2014년에 HTML5가 정식 표준이 된 이후, 현재까지 HTML5가 표준인데, 여기서 한가지 의문점이 들었다.

> 왜 아직까지 HTML5일까? HTML6는 안 나올까?

답은 "6은 앞으로 나오지 않는다"로 밝혀졌다. WHATWG는 HTML5 이후로 버전 번호를 아예 페지했다.

### 예전 방식: 버전 모델
- 예전에는 스펙을 몇 년간 다듬어서 새로운 버전이 완성되었다고 발표하는 방식을 사용했다.
- 하지만 웹의 발전 속도가 이 주기를 따라가기에는 너무 느렸다는 것이 문제였다.

### 현재 방식: Living Standard 모델
- WHATWG는 스펙 문서를 영원히 완성되지 않는 문서로 취급한다.
- 브라우저 회사들이 새로운 기능을 구현하고 다른 브라우저들과 합의가 되면, 즉시 스펙 문서에 반영된다. 그래서 HTML5라는 이름표는 계속 쓰이지만, 매달 조금씩 갱신되는 문서다.

이 철학은 과거 XHTML의 실패와도 이어진다. 이론적으로 완벽한 스펙보다, 실제로 쓰이는 기능을 표준화하는 쪽으로 무게중심을 옮긴 것이다.
